# OpenClaw — Comprehensive Project Reference (CLAUDE.md)

> **OpenClaw** is a personal AI assistant you run on your own devices. It connects to the
> messaging channels you already use (WhatsApp, Telegram, Slack, Discord, Google Chat, Signal,
> iMessage, Microsoft Teams, WebChat, and more via extensions), and can speak/listen on
> macOS/iOS/Android. The Gateway is the single control plane; the product is the assistant.

## Architecture

```
WhatsApp / Telegram / Slack / Discord / Google Chat / Signal / iMessage
 / BlueBubbles / Microsoft Teams / Matrix / Zalo / WebChat
               │
               ▼
┌───────────────────────────────┐
│            Gateway            │
│       (WS control plane)      │
│     ws://127.0.0.1:18789      │
└──────────────┬────────────────┘
               │
               ├─ Pi Agent (RPC) — AI reasoning + tool execution
               ├─ CLI (openclaw …) — terminal interface
               ├─ Control UI — web dashboard (served by Gateway)
               ├─ WebChat UI — browser-based chat
               ├─ macOS App — menu bar + Voice Wake + Canvas
               └─ iOS / Android Nodes — device capabilities
```

### Key Architectural Concepts

1. **Gateway** — Single WebSocket control plane managing sessions, channels, tools, events,
   presence, and config. Binds to `127.0.0.1:18789` by default.

2. **Pi Agent** — AI agent runtime in RPC mode with tool streaming and block streaming.
   Uses `@mariozechner/pi-agent-core`.

3. **Sessions** — `main` session for direct chats, isolated sessions for groups/channels.
   Supports activation modes, queue modes, reply-back.

4. **Channels** — Abstraction layer routing messages from any messaging platform through
   the Gateway to the agent.

5. **Nodes** — Device capabilities (camera, screen recording, notifications, `system.run`)
   exposed via `node.invoke` over the Gateway WebSocket.

6. **Tools** — Browser control, Canvas, Nodes, Cron, Sessions, Discord/Slack actions.

7. **Multi-Agent Routing** — Route inbound channels/accounts/peers to isolated agents
   with per-agent workspaces and sessions.

## Build System

### Entry Points (tsdown)

The bundler (`tsdown.config.ts`) produces these entry points in `dist/`:

| Entry                        | Purpose                         |
| ---------------------------- | ------------------------------- |
| `src/index.ts`               | Main CLI + Gateway entry        |
| `src/entry.ts`               | Alternative entry point         |
| `src/cli/daemon-cli.ts`      | Legacy CLI shim support         |
| `src/infra/warning-filter.ts`| Node.js warning filter          |
| `src/plugin-sdk/index.ts`    | Plugin SDK (npm export)         |
| `src/plugin-sdk/account-id.ts`| Plugin SDK account ID helper  |
| `src/extensionAPI.ts`        | Extension API                   |
| `src/hooks/bundled/*/handler.ts` | Bundled hook handlers       |

### Build Pipeline

```bash
pnpm build
# Runs (in order):
#   1. canvas:a2ui:bundle     — Bundle A2UI assets
#   2. tsdown                 — Bundle TypeScript → dist/
#   3. build:plugin-sdk:dts   — Generate plugin SDK .d.ts
#   4. write-plugin-sdk-entry-dts
#   5. canvas-a2ui-copy
#   6. copy-hook-metadata
#   7. copy-export-html-templates
#   8. write-build-info
#   9. write-cli-compat
```

### Workspace Packages

Defined in `pnpm-workspace.yaml`:

```yaml
packages:
  - .           # Root (openclaw)
  - ui          # Control UI (Lit + Vite)
  - packages/*  # Internal packages (clawdbot, moltbot)
  - extensions/* # All extensions/plugins
```

## Extensions & Plugins

### Extension Architecture

- Extensions live under `extensions/*` as workspace packages.
- Each has its own `package.json` with isolated dependencies.
- Plugin-only deps stay in the extension's `package.json`, **not** the root.
- Avoid `workspace:*` in `dependencies` (breaks npm install).

### Plugin SDK

Exported from `openclaw/plugin-sdk`:

```typescript
import { /* ... */ } from "openclaw/plugin-sdk";
import { /* ... */ } from "openclaw/plugin-sdk/account-id";
```

### Plugin Types

| Type       | Description                                        |
| ---------- | -------------------------------------------------- |
| **Channel**| Messaging platform integration                     |
| **Memory** | Context/memory storage (only one active at a time) |
| **Tool**   | Agent tool extension                                |
| **Hook**   | Lifecycle hook (bundled in `src/hooks/bundled/`)    |
| **Auth**   | Authentication providers                            |

### Plugin Trust Boundary

Plugins run **in-process** with the Gateway — they have the same OS privileges.
Only install plugins you trust. Use `plugins.allow` to pin trusted plugin IDs.

### MCP Support

Via `mcporter` (https://github.com/steipete/mcporter) — bridge model, not native.

## Security Model

### Defaults

- **Main session**: tools run on the host with full access (single-user).
- **Group/channel safety**: `agents.defaults.sandbox.mode: "non-main"` runs non-main
  sessions in per-session Docker sandboxes.
- **Gateway binds to loopback** (`127.0.0.1`) by default.
- **DM pairing** enabled by default on all channels.

### Sandbox Defaults

- **Allowlist**: `bash`, `process`, `read`, `write`, `edit`, `sessions_*`
- **Denylist**: `browser`, `canvas`, `nodes`, `cron`, `discord`, `gateway`

### Web Interface

- Intended for **local use only**
- Do **NOT** expose to public internet directly
- Remote access: use SSH tunnels or Tailscale serve/funnel

### Tool Filesystem Hardening

- `tools.exec.applyPatch.workspaceOnly: true` (recommended)
- `tools.fs.workspaceOnly: true` (optional)

### Security Scanning

- `detect-secrets` for automated secret detection
- Config: `.detect-secrets.cfg`
- Baseline: `.secrets.baseline`

### Docker Security

- Runs as non-root user (`node`, uid 1000)
- Use `--read-only` and `--cap-drop=ALL` for hardening

## Coding Conventions

### Style Rules

- **TypeScript ESM** with strict typing
- **No `any`** — avoid `@ts-nocheck` and `no-explicit-any` disabling
- **No prototype mutation** for shared behavior
- **Files**: aim for < 500-700 LOC; split/refactor for clarity
- **Comments**: brief comments for tricky/non-obvious logic
- **Naming**: `OpenClaw` for product/docs; `openclaw` for CLI/package/config
- **Formatting**: Oxfmt (run `pnpm format:fix`)
- **Linting**: Oxlint with type-aware rules

### UI Conventions (Lit)

- **Legacy decorators** (`@state()`, `@property()`)
- `experimentalDecorators: true`, `useDefineForClassFields: false`

### Tool Schema Rules

- No `Type.Union` in tool input schemas
- No `anyOf`/`oneOf`/`allOf`
- Use `stringEnum`/`optionalStringEnum` for enum-like values
- Avoid raw `format` property names

### Terminal UI

- Use `src/cli/progress.ts` for spinners/progress
- Use `src/terminal/table.ts` for tables
- Use `src/terminal/palette.ts` for colors (no hardcoded colors)

## Git & PR Workflow

### Commits

```bash
# Use the committer script (avoids manual git add)
scripts/committer "<msg>" <file...>

# Message style: concise, action-oriented
# Example: "CLI: add verbose flag to send"
```

### PR Rules

- **One PR = one issue/topic** — don't bundle unrelated changes
- PRs > ~5000 changed lines: exceptional only
- Don't open large batches of tiny PRs
- AI/vibe-coded PRs welcome — mark as AI-assisted
- Template: `.github/pull_request_template.md`

### Release Channels

| Channel  | Description                           | npm tag   |
| -------- | ------------------------------------- | --------- |
| `stable` | Tagged releases (`vYYYY.M.D`)        | `latest`  |
| `beta`   | Prerelease (`vYYYY.M.D-beta.N`)      | `beta`    |
| `dev`    | Head of `main`                        | `dev`     |

### Version Locations

- `package.json` (CLI version)
- `apps/android/app/build.gradle.kts` (versionName/versionCode)
- `apps/ios/Sources/Info.plist` (CFBundleShortVersionString)
- `apps/macos/Sources/OpenClaw/Resources/Info.plist`
- `docs/install/updating.md` (pinned version)

### Multi-Agent Safety

- Don't create/apply/drop `git stash` unless explicitly requested
- Don't switch branches unless explicitly requested
- Don't modify `git worktree` checkouts unless requested
- Scope commits to your changes only
- Focus reports on your edits

## Quick Start for Developers

```bash
# 1. Clone and install
git clone https://github.com/openclaw/openclaw.git
cd openclaw
pnpm install

# 2. Build UI and core
pnpm ui:build
pnpm build

# 3. Run onboarding wizard
pnpm openclaw onboard --install-daemon

# 4. Start dev loop (auto-reload)
pnpm gateway:watch

# 5. Run checks before committing
pnpm check         # format + typecheck + lint
pnpm test           # unit tests
```
